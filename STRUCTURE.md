# Структура JS-файлов

Для трекера привычек на чистом JS я бы добавил к четырём файлам из прошлого ответа ещё несколько, но заводил бы их по мере появления кода, а не заранее.

```
src/js/
  main.js            # точка входа: импорт стилей, запуск init()
  state.js           # единое состояние + подписка на изменения
  storage.js         # чтение/запись localStorage
  habits.js          # чистая логика: добавить, отметить, удалить, посчитать серию
  constants.js       # ключи localStorage, селекторы, лимиты
  components/
    habit-list.js    # отрисовка списка привычек
    habit-form.js    # форма добавления, валидация
    calendar.js      # сетка дней / прогресс
    modal.js         # попап (если будет в верстке)
  utils/
    dates.js         # форматирование дат, «сегодня», диапазон недели
    dom.js           # мелкие хелперы: создать элемент, делегирование событий
```

Что это даёт:

- **`state.js` вместо разрозненных переменных.** Один объект с привычками и функция `subscribe`: компоненты перерисовываются при изменении, а `storage.js` подписывается и сохраняет. Так отрисовка и хранение не знают друг о друге.
- **`habits.js` без обращения к DOM.** Функции принимают данные и возвращают новые. Их легко проверить и не придётся переписывать при смене верстки.
- **Один компонент на один блок верстки.** Каждый файл в `components/` экспортирует `init(rootElement)` и сам вешает свои обработчики. Имена файлов удобно держать такими же, как у блоков в CSS: `habit-list.js` и `habit-list.css`.
- **`utils/dates.js` отдельно.** В трекере почти все ошибки связаны с датами (часовые пояса, границы недели), поэтому эту логику лучше держать в одном месте.
- **`constants.js`.** Ключ localStorage и строковые селекторы не расползаются по файлам.

Два правила, которые стоит принять сразу:

1. Стили импортируйте из `main.js` (`import '../styles/index.css'`), а `<link>` из `index.html` уберите: тогда Vite сам обрабатывает CSS и обновляет его без перезагрузки.
2. Элементы ищите по `data-`атрибутам (`data-habit-id`, `data-action="toggle"`), а не по классам. Классы остаются только для стилей, и переверстка не ломает JS.

Если проект останется на один экран, папку `components/` можно не создавать и обойтись одним `render.js`. Делить стоит тогда, когда файл перевалит за 150–200 строк.
